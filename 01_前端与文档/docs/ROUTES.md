# 精选摄影路线维护

路线由 `api/src/routes/routes.catalog.ts` 内的 `ROUTE_CATALOG` 维护，不需要管理后台，不创建或复制作品。当前上海路线仅为演示编排，未经实地验证。

## 修改步骤

1. 确认要引用的机位已公开，记录作品详情链接中的 UUID。不要通过重跑种子脚本来恢复或凑齐机位。
2. 在目录中增加或修改路线：填写唯一 `id`、名称、省市、简介、主题、更新日期、出行提示、演示标记及声明。
3. `stops` 数组顺序就是展示顺序，每站填写 `spotId`、`suggestedTime`、`note`。一条路线包含 2 至 20 个不重复站点；目录最多 50 条。
4. 在项目根目录运行配置检查：

   ```powershell
   .\.local\node\node.exe .\api\node_modules\ts-node\dist\bin.js .\api\src\routes\check-catalog.ts
   ```

5. 停止旧 API，再双击 `start-local.cmd`；使用生产构建时先重新构建。打开 `/api/v1/routes` 以及小程序“发现 → 精选摄影路线”核对。

## 配置约束

- 路线 ID 使用小写字母、数字和短横线，不超过 64 字符；每条路线及其站点均不能重复。
- `updatedAt` 使用有效的 `YYYY-MM-DD`；`preparation` 为 1 至 10 条提示；文本长度及 UUID 格式由校验器检查。
- 配置校验只检查格式。作品是否存在、公开且属于该地区，以接口查询时的数据库状态为准。
- 隐藏、审核中、删除、不存在或迁往其他城市的作品不公开返回。保留配置关系，恢复有效后重新出现；不足两个有效站点时路线隐藏。
- 无真实照片时使用已有占位。不编造交通时间、距离、开放时段、门票或实地考察结论，不把跨江路段标为连续步行。

修改顺序和建议不改变发现页筛选、地图或用户收藏。此版本无路线收藏、管理页面或自动路线规划。
