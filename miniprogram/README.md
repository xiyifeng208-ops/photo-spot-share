# 小程序端说明

## 导入与运行

1. 微信开发者工具 → 导入项目 → 选择本目录（`miniprogram/`）。
2. 详情 → 本地设置 → 勾选 **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**。
3. 编译。默认走 `config/index.js` 的 `dev` 环境：`useDevLogin: true`，用 `dev:<设备ID>` 静默登录，
   不需要 AppID 也能连本机后端。

## 页面结构

| 页面 | 路径 | 作用 |
| --- | --- | --- |
| 发现 | `pages/discover/index` | **默认首页**。机位列表流，先出全国列表，定位回来后自动切到所在城市；上拉分页 |
| 地图 | `pages/map/index` | 第二个 Tab。全屏地图，按视野拉点位；低 zoom 显示城市聚合；点 marker 弹底部卡片 |
| 我的 | `pages/mine/index` | 我创建的机位，可编辑 / 删除 |
| 详情 | `pages/spot/detail` | 样张轮播、拍摄参数、怎么拍 / 怎么到、导航按钮 |
| 创建 | `pages/spot/create` | 两步式：地图选点 → 填写拍摄建议与样张；带 `?id=` 时进入编辑模式 |

## 关键实现点

- **选点**：图钉固定在屏幕中心，`bindregionchange` 的 `end` 事件触发 `getCenterLocation`，
  再防抖 500ms 调后端 `/geo/reverse` 拿地址；连续拖动会用请求序号丢弃过期响应。
- **视野查询**：`MapContext.getRegion()` 拿 bbox，带上 `zoom` 与用户位置请求 `/spots`；
  同样用序号防止快速拖动时响应乱序覆盖。
- **导航**：`wx.openLocation` 打开微信内置地图（含路线规划，可跳腾讯地图），无需任何域名白名单。
- **上传**：`utils/upload.js` 先调 `/uploads/photos/sign` 拿凭证；`local` 驱动走 `wx.uploadFile` 传到后端，
  `cos` 驱动走官方 `cos-wx-sdk-v5` 直传。两种驱动页面代码完全一致。
- **登录态**：`utils/request.js` 遇到 401 会清会话、自动重登并把本次请求重放一次（仅一次，避免死循环）。
- **首屏**：发现页进入即用「全部城市」拉列表，登录与定位放后台并行；定位回来后如果用户没手动切过城市，才自动切到所在城市并刷新一次。地图页同样是"先渲染、后校正"。

## 兼容性说明

页面在 `<map>` 之上使用了普通 `view` 做浮层（顶栏、底卡、按钮），依赖小程序的**同层渲染**能力，
即基础库 **2.7.0+**。`project.config.json` 已指定 `libVersion: 3.5.5`，正常不需要额外处理。
选点页的中心图钉用的是 `cover-view`，在更老的客户端上也能正常显示。

## 地图在开发者工具里加载不出来怎么办

模拟器渲染原生地图组件偶发失败（工具日志会出现 `routeTo appLaunch/switchTab timeout`、
`WXML bridge ack timeout`，甚至进程崩溃）。这种情况下 `getRegion` 既不回调 `success` 也不回调
`fail`，页面会一直停在"加载中"——代码里已经加了超时兜底和降级，但地图本身仍然出不来。
按顺序试：

1. 详情 → 本地设置：**取消勾选「编译热重载」**（`compileHotReLoad` 会放大文件监听的抖动）。
2. 工具栏 → 工具 → **清除缓存 → 全部清除**，然后重新编译。
3. 设置 → 通用设置：切换一次「使用硬件加速」（关掉或打开，取决于当前状态）。
4. 完全退出开发者工具再打开（它崩过一次后进程状态会不干净）。
5. **扫码真机预览**。真机不走模拟器的渲染层，如果真机地图正常，就能确定是工具侧问题。

代码侧的行为（已用 `tools/test-map-page.mjs` 固化）：地图 2.5 秒没就绪就降级成"地图没能渲染出来"
面板，给出全国机位汇总和「去发现页看列表」入口；地图若随后渲染完成，会自动恢复并重新拉点位，
不需要用户操作。

### 实际排查结论（2026-09-15）

先做了 `tools/map-sandbox` 最小工程对照，确认这台机器的开发者工具能正常渲染地图组件
（三格地图都触发 `updated`，`getRegion` 也成功回调）。所以问题在业务页面，最终两处改动解决：

1. 删掉 `app.json` 里的 `lazyCodeLoading: "requiredComponents"`（启动优化，但会让地图这类
   原生组件初始化失败）。
2. 地图宽限期从 2.5 秒放宽到 **8 秒**：启动时要同时跑登录、定位、首屏请求，地图的 `updated`
   事件会更晚，原来的阈值会把"还没来得及渲染"误判成"渲染失败"，提前弹出降级面板。

地图页顶栏那行灰色调试信息（`updated×N ready=Y/N getRegion=ok/fail 等待Ns`）由
`config/index.js` 里的 `debug` 开关控制，排查完改成 `false` 即可。

### 从子页面返回后地图空白

现象：进创建页/详情页再返回，地图区域空白。此时调试行显示 `updated×N ready=Y getRegion=ok`——
组件活着、事件照常触发、视野查询也成功，只是画面画不出来，属于原生组件重新挂载后的渲染丢失，
JS 侧无法感知。

处理方式：返回时只重建 `MapContext` 并重新计时宽限期，**不**自动卸载/挂载地图——自动重建一旦失败，
地图就再也回不来了，代价比收益大。真出现画面空白时，点面板上的「重新加载地图」按钮才会执行重建
（`mapVisible` 先 false 再 true）。重建前会用 `getRegion` 记住当前视野中心和缩放级别，不会跳回默认位置。

### 缩放地图时地图消失

原因：把用户在手势里产生的缩放级别**写回了 `map` 的 `scale` 属性**。捏合过程中反复更新原生组件
的属性会打断手势，DevTools 里直接表现为地图白掉。

处理方式：用户缩放只记录在页面实例的 `viewScale` 上，只用于 `/spots?zoom=` 查询，**绝不写回
`scale` 属性**。`scale` 只在程序主动移动地图时才修改——「回到我的位置」、点击聚合气泡、以及
返回时重建地图（重建会把 `viewScale` 带过去，所以缩放级别不会跳回默认值）。

### 三种失败原因要分开看

地图页的失败提示不再是一句话，`failReason` 分三种，顶栏灰字与面板文案都会对应：

| failReason | 含义 | 处理 |
| --- | --- | --- |
| `map` | 地图组件根本没初始化（底图没画出来） | 面板 + 全国汇总 + 去发现页；「重新进入页面」走 `wx.reLaunch` 整页重建 |
| `region` | 地图在渲染，但连续几次拿不到可视范围（原生组件重绘期间会丢回调） | 自动重试 2 次（600ms / 1.5s 退避）后才判定 |
| `data` | 视野拿到了，是接口请求失败 | 重试 1 次，然后提示检查后端 |

地图元素**永远挂载**，不做 `wx:if` 卸载/挂载——原生地图重建一旦失败就再也不会触发 `updated`，
那正是「`updated×0` 死局」的成因。所以恢复手段一律走整页重建。

`getRegion` 的超时是 5 秒。这个接口在原生化地图重绘期间会间歇性丢回调（表现为
`updated×N ready=Y` 但 `getRegion=ok/fail`），属于原生组件的正常抖动，不能据此判定地图坏了。

## 离线回归测试

页面逻辑可以在没有开发者工具的情况下验证（用桩件替换 `wx` API，直接跑页面真实代码）：

```bash
node tools/test-map-page.mjs
node tools/test-discover-page.mjs
node tools/test-create-page.mjs
```

覆盖：

- **地图页**：永不回调（灰白卡死）、正常渲染、延迟就绪自动恢复、接口失败、返回页时旧 `MapContext` 失效、
  缩放不写回 `scale` 属性、`getRegion` 间歇性丢回调要能自愈、「重新进入页面」走整页重建。
- **发现页**：定位慢时列表先渲染、定位回来后自动切城市、用户手动切过则不被覆盖、定位失败也不卡 loading。
- **创建页**：没配高德 Key 时手动填写的地址要真的进到 `geo.address`；配了高德时地址自动填充。

## 上线前必改

1. `config/index.js`：`ENV` 改成 `'prod'`，填上正式 `apiBaseUrl`。
2. 走 COS 直传时：`npm i cos-wx-sdk-v5`，用开发者工具「工具 → 构建 npm」。
3. 小程序后台配置 request / uploadFile 合法域名，并申请开通 `wx.getLocation` 接口权限。
4. 在 `app.json` 的 `requiredPrivateInfos` 已声明 `getLocation`，隐私协议里同步声明用途。
