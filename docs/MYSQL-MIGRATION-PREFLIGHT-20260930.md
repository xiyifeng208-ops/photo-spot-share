## 3. 数据兼容性检查

本次已检查的数据中，未发现：

- 非法 UUID、字段超长、目标 ASCII 标识字段中的非 ASCII 值。
- 重复 openid、照片 object_key、票据 object_key、照片排序、审核 trace_id、重复举报组合。
- 失效的用户/机位/封面引用，照片或票据作者归属不一致。
- 非法状态、方向/焦段枚举、无效或重复的推荐时段/季节数组元素。
- 经纬度越界，PostGIS location 的坐标与 lat/lng 不一致，或源 SRID 不等于 4326。
- 非法难度、负浏览数、尺寸/排序/尝试次数超出已检查目标范围、不可转换的时间值。

照片、票据、审核、举报均为空，相关检查的零异常是“没有待检查记录”，不是已验证真实图片业务数据的迁移。

### 必须显式处理的事项

1. **六个机位全部无照片。** 目标数据库结构本身可以保存这类历史记录，但不满足后端新建/替换照片时“至少一张”的业务要求。不得自动删除这些机位、伪造照片或默默跳过；若用户确认完整保留，后续迁移需将它们记为明确的历史数据例外。
2. **时间精度不同。** 三个用户及六个机位存在非零微秒部分；目标 DATETIME(3) 只能保存毫秒。迁移需明确统一精度策略并在校验时使用相同规则，不能声称微秒完全无损。原始精度应保留在 PostgreSQL 备份中。
3. **举报 updated_at 是目标新增字段。** 当前源 `spot_reports` 没有该列。虽然现在零行，通用迁移脚本仍需定义回填规则，例如按 created_at 初始化，并写入迁移说明。
