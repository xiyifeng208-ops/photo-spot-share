# 产品介绍：机位地图

> 一句话：把「照片 + 拍摄方法 + 精确位置」绑成一个能直接导航过去的对象，让普通人也能复制别人验证过的出片视角。

## 一、问题：拍照的门槛早就不在设备

想拍出好照片，真正的难点是四个问题：**在哪拍、几点去、站哪个位置、怎么取景。**

- 这些经验散落在社交平台的图文和评论区里。看完一篇攻略，还得自己拼坐标、切到地图 App 搜索地点——信息和行动是断开的。
- 地图产品只到"景点"这一层粒度。可同一个观景台，站在左边和右边拍出来完全是两张照片。
- 缺的是"机位"这个更细的实体：它是位置、朝向、时间、焦段的组合，而不是一个 POI。

## 二、方案：把机位做成可导航的对象

用户在地图上标注自己发现的机位，上传样张并写下拍摄建议；其他人在同一张地图上看到这些机位，点进去看参数、看样张，然后一键导航过去。

一个机位 = 位置（GCJ-02 坐标 + 地址）+ 样张 + 结构化拍摄参数 + 到达提示。

## 三、核心功能

1. 地图浏览：按视野拉取点位，缩放级别低于 9 时自动按城市聚合成"上海市 3"这样的气泡，放大才展开明细；发现页按城市筛选、上拉分页，卡片直接展示样张、距离与参数标签。
2. 创建机位：两步式——拖动地图选点（服务端高德逆地理自动解析省市区与地址），再填写标题、样张、拍摄建议。拍摄信息结构化：机位朝向、推荐时段、推荐季节、推荐焦段、到达难度、到达提示。
3. 详情与导航：样张轮播 + 拍摄参数 + 「怎么拍」「怎么到」+ 作者与浏览量；一键调起微信内置地图做路线规划，不跳第三方 App；作者可编辑/删除自己的机位。
4. 内容安全：文本走 msg_sec_check、图片走 media_check_async；新机位先进入"审核中"，通过后自动公开，命中风险自动隐藏。用户可举报违规内容，同一机位被 3 个不同用户举报自动下线，配套极简运营接口用于人工处置。

## 四、创新点

1. 以"机位"而非"景点"为最小单位——同一点位按朝向、焦段、时段分别记录，粒度比传统地图细一个量级。
2. 结构化拍摄信息——朝向、时段、季节、焦段、难度都可筛选可比较，而不是一段没有结构的攻略长文。
3. 内容直接可执行——每个机位都是一条能走完的路线的终点，从"看到"到"走到"只剩一次点击。
4. 面向真实环境的工程韧性——地图组件不可用时自动降级为列表并给出机位汇总；接口地址跟随请求来源自动适配；坐标、地址、城市全程统一 GCJ-02，不做易错的坐标系转换。

## 五、技术实现

- 前端：微信小程序原生。用微信原生 map 组件渲染（免 Key、性能好），高德只在服务端用于逆地理编码，Key 不下发前端。
- 后端：NestJS + PostgreSQL/PostGIS。空间字段加 GIST 索引做视野查询，分组统计做城市聚合；统一错误结构、限流、软删除。
- 存储：可切换的存储驱动。开发用本地磁盘加 /static，生产切腾讯云 COS 加 CDN；上传凭证限定在 uploads/{userId}/ 目录下。
- 内容安全：文本走 msg_sec_check，图片走 media_check_async，检测结果经消息推送回调落库，另有超时兜底扫描。
- 部署：Docker Compose 加 Nginx，postgres、api、nginx 三容器，HTTPS 终止与图片静态分发。

## 六、工程状态（可演示、可验证）

功能闭环已全部跑通：地图浏览、创建机位、详情、一键导航、发现流、我的管理。

测试方面：后端 107 个单元测试与 9 个端到端用例（跑在真实 PostGIS 上），小程序端 50 项页面级离线回归，全部通过。

合规方面：内容机审、举报处置、用户协议与隐私政策页、运营接口均已完成；剩余为域名备案、HTTPS、小程序备案与提审，清单见 docs/LAUNCH.md。

## 七、路线图

- 近期：上线并积累真实机位数据；引导用户填写昵称头像，完善作者展示。
- 中期：机位点赞收藏与排序、按"最佳拍摄时段"提醒、路线串联（一天串起多个机位）。
- 长期：机位数据沉淀为"城市拍照热度地图"，为文旅与小众机位传播提供数据支撑。
